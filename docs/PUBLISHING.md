# Регламент публикации проектов

Каталог пополняется по стадиям разработки: проект появляется на сайте на первой же стадии и дальше обновляется по мере продвижения. Посетитель видит не только готовый результат, но и путь к нему.

## 1. Что попадает в каталог

**Значимый проект** — самостоятельная работа с результатом, который можно показать: объект проектирования (здание, интерьер), сайт, приложение, 3D-сцена, инструмент.

Не публикуются: разовые скрипты, эксперименты и учебные примеры, настройка окружения и инструментов.

## 2. Стадии

Две дорожки — по типу проекта.

| Дорожка | `track` | Стадии (`stage`) |
|---|---|---|
| Цифровые проекты | `digital` | `idea` идея → `prototype` прототип → `development` разработка → `beta` бета → `release` релиз → `support` поддержка |
| Здания и интерьеры | `architecture` | `concept` концепция → `sketch` эскизный проект → `documentation` рабочая документация → `construction` реализация → `completed` завершён |

Правила:
- стадия ставится по факту, без опережения;
- одна пройденная стадия — одна запись в хронологии (`timeline`);
- стадии можно пропускать, назад не откатываем — вместо этого новая запись с пояснением.

## 3. Формат записи

Один проект — одна папка: `src/content/projects/<slug>/` с файлом `index.md` и изображениями рядом.

```markdown
---
title: "Название проекта"
summary: "Одно-два предложения: что это и для чего."
track: digital            # digital | architecture
stage: prototype          # текущая стадия из дорожки
started: 2026-09-21
updated: 2026-10-05
cover: ./cover.jpg        # пропорция 1,618 : 1
tags: ["интерьер", "3D"]
stack: ["Blender", "Archicad"]
links:                    # необязательно
  demo: ""
  repo: ""
featured: false           # показывать на главной
draft: false              # true — не публикуется
timeline:
  - stage: idea
    date: 2026-09-21
    note: "Что сделано на стадии — два-три предложения."
    images: []
  - stage: prototype
    date: 2026-10-05
    note: "…"
    images: ["./prototype-01.jpg"]
---

Подробное описание проекта: задача, решение, результат.
```

`<slug>` — латиница, строчные буквы, дефисы: `dom-u-ozera`, `three-viewer`.

## 4. Что публикуется на каждой стадии

| Стадия | Минимум для публикации |
|---|---|
| Первая (идея / концепция) | Название, описание задачи, дорожка, теги; обложка — по возможности |
| Промежуточные | Запись в хронологии: что сделано, 1–3 изображения (скриншоты, рендеры, схемы) |
| Релиз / завершён | Итоговое описание, обложка, галерея, ссылки на демо или репозиторий (если публичны) |

## 5. Порядок публикации

1. Создать или обновить запись проекта: `stage`, `updated`, новая запись в `timeline`, изображения.
2. Изображения — оптимизированные копии (длинная сторона до 2400 px); оригиналы остаются в папке проекта и не изменяются.
3. Проверить сборку: `npm run build`.
4. Коммит и push в `main` — GitHub Actions пересоберёт и опубликует сайт.
5. Проверить страницу проекта на сайте.

Первая публикация каждого нового проекта согласуется с автором: название, описание и материалы, которые уйдут на сайт. Дальнейшие обновления по стадиям публикуются без дополнительного согласования.

## 6. Что не публикуется

- Материалы и данные заказчиков — адреса, имена, чертежи, фото объектов — без явного согласия автора.
- Контактные данные.
- Содержимое закрытых репозиториев.
- Токены, ключи, служебные пути и имена.

При сомнении — не публиковать и уточнить.

## 7. Оформление

- Язык — русский.
- Без курсива: акцент передаётся насыщенностью и цветом.
- Подпись автора на сайте — «Иван».
